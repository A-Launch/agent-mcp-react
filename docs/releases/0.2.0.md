# `@agent-mcp/react` 0.2.0

The first release published from this repository. `v0.2.0` names the tree whose manifest declares
`0.2.0` — the tag is the release rather than a marker placed near it.

## What changed since 0.1.0

Nothing in the library's behaviour. `src/` is unchanged: no capability, no tool, no lifecycle
guarantee and no error code differs from what [0.1.0](0.1.0.md) shipped. What this release adds is
everything a reader outside the project needs in order to use it, judge it, or contribute to it.

- **A README written for someone who has never seen the project** — what it does, whether it fits,
  how to install it without a registry, the minimal wiring that actually compiles, what you have to
  supply, and what will bite you.
- **A contributor guide that owns every convention** (`CONTRIBUTING.md`), a code of conduct, a
  security policy, and issue and pull-request templates.
- **One health gate.** `pnpm gate` runs the whole thing in one command; `package.json#scripts` is the
  only place its membership and order are stated.
- **A CI workflow** whose `gate` job is the check branch protection requires, with its actions pinned
  to full commit SHAs. It is requestable on any ref, because a push cannot always be relied on to
  produce a run.
- **A publish check** (`pnpm verify:public`) that decides what may appear in this tree, and ships
  here so a reader can see the rules rather than take them on trust.

## Two defects fixed, both in the test harness

Neither is a library defect, and both are recorded in full under [../issues/](../issues/).

- **The end-to-end suite raced itself across engines.** Cases identified their own page by reasoning
  about a globally shared list, which is not scoped to the test reading it. Each case now reads the
  identity its own page minted. Proved by holding a neighbour page connected for a whole run: the old
  mechanism fails deterministically, the new one passes.
- **The published release tag carried nothing.** It was a lightweight pointer with no message. It is
  now annotated, and its message is composed from this tree's own manifest rather than copied from
  anywhere, so it cannot describe a version this tree does not declare.

## What this release still does NOT claim

The browser matrix remains a support **target**, not verified support — the same limitation
[0.1.0](0.1.0.md) stated, unchanged and restated here rather than quietly dropped. Three engines under
one automation driver are not nine browser-and-version combinations. What has been run and what has
not is in [../browser-support.md](../browser-support.md).

Level 2 (DOM) tools remain experimental. `runtime.evaluate` remains disabled by default and is not
enabled to unblock anything.
