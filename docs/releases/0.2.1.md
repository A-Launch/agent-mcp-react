# `agent-mcp-react` 0.2.1

A packaging fix. Nothing in the library's behaviour differs from
[0.2.0](0.2.0.md); `src/` is byte-identical.

## Install 0.2.1, not 0.2.0

**`0.2.0` is broken and deprecated.** Its published manifest declared every subpath as `./src/*.ts`
while `files` ships only `dist/`, so every import from it fails at resolution.

## What went wrong

`publishConfig` field overrides — which rewrite the `exports` map to point at `dist/` — are a **pnpm**
feature. `pnpm pack` applies them; `npm publish` does not. The release workflow published the working
tree with npm, so the manifest that reached the registry was the development-time one, pointing at
files the package deliberately excludes.

Every check was green throughout, and honestly so: `verify:package` packs with pnpm and asserts the
tarball resolves every export it declares, which it did. **The artifact it validated was never the
artifact being uploaded.** That is the whole defect — not a missing check, but a check pointed at a
different object than the one that shipped.

## The fix

The workflow now packs with pnpm, runs `verify:package` against that tarball, and hands npm **that
file** rather than the working tree. npm reads the manifest from inside a tarball, so what is verified
and what is published are the same bytes.
